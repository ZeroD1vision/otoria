# ADR-0001: Способ IPC между `soma` и `anima` на Orange Pi

**Статус:** Предложено
**Дата:** 2026-09-29
**Участники:** Саша, Артемий, Пахан

## Контекст

`soma` (аудио-демон Саши) захватывает звук, детектирует hotword и VAD, и должен передать готовый PCM/Opus-поток процессу `anima` (Go-оркестратор), работающему на том же Orange Pi. Нужно выбрать межпроцессное взаимодействие: Unix-сокет, shared memory, именованные пайпы.

## Рассмотренные варианты

1. **Unix domain socket (поток)** - просто, есть готовая поддержка и в C/C++, и в Go; накладные расходы на копирование данных небольшие при таком битрейте аудио.
2. **Shared memory + семафоры** - минимальная задержка и copy-overhead, но сложнее в реализации и отладке, избыточно для аудио-потока такого размера.
3. **Named pipe (FIFO)** - просто, но без нативной поддержки границ сообщений и сложнее с переподключением при рестарте одной из сторон.

## Решение

_Заполняется по итогам обсуждения в issue #TBD._ Кандидат по умолчанию - Unix domain socket с бинарным фрейм-протоколом (длина + тип кадра + payload), описанным в `proto/audio.proto`.

## Последствия

Формат кадра фиксируется в `proto/audio.proto` и требует approve всех троих при изменении (см. CODEOWNERS). Детектор стоп-слова (hotword) и вопрос резервного серверного слоя фильтрации - отдельный ADR-0002.
