# Версионирование и релизы

Каждый из трёх бинарников версионируется **независимо**, т.к. живёт на разных устройствах и обновляется в разное время.

## Схема версий

**Semantic Versioning 2.0.0**: стандартный `MAJOR.MINOR.PATCH`.

- `MAJOR` - несовместимое изменение протокола (`proto/`) или блокирующее изменение.
- `MINOR` - новая функциональность, обратно совместимая.
- `PATCH` - багфиксы, без изменения поведения контрактов.

## Git-теги

Формат тега: `<module>-vX.Y.Z`.

Так как модули разные, единого тега на весь репозиторий нет - только когда фиксируется совместимый релиз всей системы: `system-vX.Y.Z` (такой тег ставится, когда все три бинарника протестированы вместе как единое целое).

## Изменения протокола (`proto/`)

Любое изменение в `proto/` обязано:
1. Быть согласовано всеми тремя (см. CODEOWNERS).
2. Поднимать `MAJOR` версию у **обоих** сторон контракта (например, если меняется `audio.proto`, то и `soma`, и `anima` получают breaking bump).
3. Фиксироваться записью в `CHANGELOG.md` соответствующих модулей и ADR при архитектурном характере изменения.

## CHANGELOG

Каждый модуль ведёт свой `CHANGELOG.md` по формату [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), генерируемый из Conventional Commits (`scripts/changelog.sh`, опционально автоматизируется через `git-cliff` в CI).

## Чек-лист для релиза

- [ ] CI зелёный (build, lint, тесты) для затронутого модуля.
- [ ] `CHANGELOG.md` модуля обновлён.
- [ ] Тег поставлен и запушен (`git tag <module>-vX.Y.Z && git push --tags`).
- [ ] Для `system-v*` - все три модуля проверены вместе на стенде.
